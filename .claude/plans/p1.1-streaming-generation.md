# P1.1 Plan: Script Streaming Generation

## Goal
Reduce perceived wait time during script generation (currently 5–15s of spinner) by streaming the LLM response to the frontend and showing a live preview.

## Current State
- `/api/chat` in `server.js` proxies to Ollama with `stream: false`
- `generateScript()` in `helpers.js` calls `callModel()` twice (core + objections) in parallel, waits for full JSON
- StudioView shows a static loading spinner until `generateScript()` resolves

## Proposed Architecture

### 1. Backend: Add streaming proxy endpoint
**New endpoint:** `POST /api/chat/stream`
- Same auth/api-key injection as existing `/api/chat`
- Sets `stream: true` on the Ollama request
- Pipes the raw NDJSON/SSE stream straight through to the client without buffering
- Response headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`
- Handles both NDJSON (Ollama native) and SSE (OpenAI-compatible cloud APIs) by just forwarding bytes

### 2. Frontend: Streaming API helper
**New function:** `callModelStream(system, prompt, onChunk)` in `helpers.js`
- Makes `fetch()` to `/api/chat/stream`
- Uses `response.body.getReader()` + `TextDecoder`
- Parses NDJSON lines as they arrive (`{"message":{"content":"..."}}`)
- Calls `onChunk(fullTextSoFar, latestChunk)` for each token
- Returns final accumulated text when stream ends

**New function:** `generateScriptStream(opts, onProgress)` in `helpers.js`
- Calls `callModelStream` for the core script prompt
- Calls `callModelStream` for the objection prompt (in parallel)
- `onProgress({ stage: "core" | "objections", status: string, text: string })`
- Parses JSON at the end and returns the same shape as `generateScript()`

### 3. Frontend UI: Live generation preview
**StudioView changes:**
- Replace static `loading` state with streaming state
- Show a live preview panel that displays the accumulating JSON text
- Stage indicators:
  1. "Analyzing product & methodology…" (0–20%)
  2. "Writing call segments…" (20–80%) — live text appears here
  3. "Preparing objection responses…" (80–100%)
- Once complete, parse JSON and switch to formatted script view (existing Cockpit)
- Keep non-streaming `generateScript()` for on-demand language generation in ScriptCockpit (simpler)

## Why This Approach
- **Raw byte piping** on the backend avoids buffering the entire response, minimizing latency
- **NDJSON parsing** on the client is simple and matches Ollama's native streaming format
- **Live text preview** gives users genuine feedback that generation is happening
- **Stage labels** add structure so users understand what's being built
- **Backward compatible:** `generateScript()` stays untouched; only StudioView initial generation uses streaming

## Risks & Mitigations
| Risk | Mitigation |
|------|-----------|
| Cloud API returns SSE instead of NDJSON | Client parser handles both: splits on `\n`, ignores `data: ` prefix if present |
| Partial JSON can't be parsed mid-stream | We only parse at the end; mid-stream shows raw text |
| Stream interrupted / network error | Wrap in existing retry logic; fall back to non-streaming on final retry |
| Two parallel streams complicate UI state | Use `Promise.all` with individual `onProgress` callbacks; clear state machine |

## Open Question
Should the objection prompt also stream, or can it stay non-streaming since it's shorter? **Recommendation:** Stream both in parallel so the total wait time is `max(coreTime, objTime)` rather than `sum`. The UI shows objections stage only after core completes.
